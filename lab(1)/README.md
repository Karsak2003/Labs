# cc_search — CLI-поиск по архиву Common Crawl

Консольное приложение для поиска страниц в веб-архиве [Common Crawl](https://commoncrawl.org/)
через лёгкий **CDX-индекс** с опциональной точечной загрузкой текста из **WARC-файлов**
по HTTP-заголовку `Range`.

Практическая работа №1 курса «Интеллектуальный анализ веб-данных» (Практика 1: консольное приложение Common Crawl).

## Архитектура

Common Crawl хранит данные в двух слоях:

| Слой | Содержимое | Стоимость доступа |
|------|-----------|-------------------|
| **CDX-индекс** | URL, дата архивации, HTTP-статус, `offset`, `length`, `filename` | Лёгкий: поиск без загрузки контента |
| **WARC-файлы** | Полные HTTP-ответы (заголовки + тело) | Тяжёлый: сотни ТБ; грузится только нужный байтовый диапазон |

Пайплайн приложения (порядок этапов — по требованиям практики):

```
1. CLI (argparse)                 -- контракт приложения
        |
2. CDX-поиск (cdx-toolkit)        -- только индекс, без WARC
        |  rows: url, timestamp, status, mime, offset, length, filename
        |  (кэш успешных ответов: cdx_cache/)
        |
3. [--show-text] WARC Range       -- httpx + warcio + beautifulsoup4
        |  bytes=offset-(offset+length-1) -> title + фрагмент текста
        |
4. Вывод таблицы (tabulate)       -- URL | Дата архивации | Заголовок | [Текст]
```

Ключевой принцип: **быстрый поиск по индексу** и **тяжёлая загрузка контента только по требованию** (`--show-text`).

- Python **3.10+**

|-----------|-----------|

| `warcio` | Потоковое чтение WARC-записей |

| `beautifulsoup4` | Извлечение `<title>` и текста из HTML |
| `tabulate` | Форматированный вывод таблицы |

## Использование

```bash
# Быстрый поиск по домену (только CDX)
python cc_search.py Perm PNIPU --domain pstu.ru --limit 5

# С загрузкой фрагмента текста страницы (WARC, Range-запрос)
python cc_search.py ITAS --domain pstu.ru --limit 5 --show-text

# Другой снапшот / свой диапазон дат
python cc_search.py Perm --domain pstu.ru --snapshot CC-MAIN-2024-10
python cc_search.py Perm --domain pstu.ru --from-ts 20240101 --to-ts 20241231

# Подробный лог в файл (логи идут в stderr)
python cc_search.py Perm --domain pstu.ru --verbose 2> debug.log

# Принудительно свежий запрос (игнорировать свежий кэш)
python cc_search.py Perm --domain pstu.ru --no-cache
```

Пример вывода (`--show-text`):

```
+-----+------------------------------------+---------------------+------------------+----------------------+
|   # | URL                                | Archive Date        | Title            | Text Fragment        |
+=====+====================================+=====================+==================+======================+
|   1 | https://pstu.ru/...                | 2026-10-14 03:22:11 | Пермский Политех | ...fragment...       |
+-----+------------------------------------+---------------------+------------------+----------------------+
```

## Аргументы командной строки

| Аргумент | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `keywords` | позиционные, 1+ | — | Ключевые слова (см. [семантику](#семантика-keywords)) |
| `--domain` | опция | — | Домен поиска, напр. `pstu.ru` (нормализуется: lower, без `www.`) |
| `--limit` | int | `10` | Максимум строк в итоговой таблице |
| `--show-text` | флаг | выкл. | Загружать title и фрагмент текста из WARC |
| `--snapshot` | str | `CC-MAIN-2026-43` | Снапшот Common Crawl; маппится в диапазон дат |
| `--from-ts` | str | из `--snapshot` | Начало диапазона, `YYYYMMDD[HHMMSS]` (переопределяет snapshot) |
| `--to-ts` | str | из `--snapshot` | Конец диапазона |
| `--max-retries` | int | `2` | Попыток CDX-запроса до срабатывания circuit breaker |
| `--timeout` | int | `25` | Wall-clock кап (сек) на один CDX-запрос |
| `--no-cache` | флаг | выкл. | Игнорировать свежий кэш (кэш всё равно используется как fallback при сбое) |
| `--verbose` | флаг | выкл. | Уровень логирования DEBUG |

## Как работает приложение

1. **CLI.** `argparse` описывает контракт; при отсутствии `--domain` и если первое слово
   не похоже на домен (нет `.`) — выход с кодом `2` и подсказкой.
2. **CDX-поиск.** Шаблон `*.{domain}` (domain-match, индексный). Диапазон дат вычисляется
   из имени снапшота: ISO-неделя `CC-MAIN-YYYY-WW` → понедельник недели −14 дней … +21 день;
   `CC-MAIN-YYYY` → весь год. Это сужает список кроулов, которые перебирает `cdx-toolkit`.
   Для запаса под фильтрацию ключевых слов запрашивается `min(limit*5, 50)` строк.
3. **WARC (только `--show-text`).** Для каждой строки: `GET https://data.commoncrawl.org/{filename}`
   с `Range: bytes={offset}-{offset+length-1}`; запись читается `warcio.ArchiveIterator`,
   кодировка определяется по `Content-Type` (fallback: `utf-8`, `cp1251`); `bs4` извлекает
   title и первые 200 символов текста. Между загрузками — пауза 1 с (вежливый rate ≤ 1 req/s).
4. **Вывод.** `tabulate`, стиль `grid`, ограничение ширины колонок. Без `--show-text`
   колонка `Title` содержит `-` (CDX не хранит заголовки).

## Семантика keywords

**CDX — это индекс URL, а не полнотекстовый поиск.** Найти «все страницы со словом X
по всему архиву» через CDX невозможно. Поэтому:

- `--domain` задаёт область поиска (что искать *где*);
- `keywords` — клиентский фильтр: подстрока в URL (без учёта регистра),
  а с `--show-text` — также в title и фрагменте текста;
- если совпадений нет, показываются кандидаты домена с предупреждением в логе
  (честное поведение: «предел возможностей инструмента»);
- кириллические слова в URL практически не встречаются — для них нужен `--show-text`.

## Кэширование

Каталог `cdx_cache/` создаётся автоматически.

| Файл | Ключ (sha1[:16]) | Содержимое |
|------|------------------|-----------|
| `cdx_*.json` | `pattern \| from_ts \| to_ts \| fetch_limit` | Список CDX-строк успешного запроса |
| `warc_*.json` | `filename \| offset \| length` | `{title, snippet}` загруженной записи |

Поведение:

- **cache hit** — мгновенный ответ без сети;
- **успешный запрос** — сохраняется в кэш;
- **сбой сервиса** — приложение отдаёт кэш, если он есть (демонстрация полной цепочки
  возможна даже во время деградации индекса);
- `--no-cache` — не читать свежий кэш, но использовать его как fallback при сбое.

## Отказоустойчивость

| Механизм | Реализация | Зачем |
|----------|-----------|-------|
| **Circuit breaker** | после `--max-retries` неудач — стоп, без перебора снапшотов | не превращать сбой в часы шторма запросов |
| **Wall-clock кап** | CDX-запрос в daemon-потоке с `join(--timeout)` | обрывает внутренний шторм повторов `cdx-toolkit` (backoff 2→4→8→16→32→60 с и пагинацию page 0..45 на 404) |
| **Вежливые паузы** | 3·attempt с между попытками CDX; 1 с между WARC-загрузками | требования FAQ Common Crawl к rate limit |
| **Graceful degradation** | WARC не загрузился → `- (load failed)`; CDX недоступен → кэш или код `1` | приложение не падает и не виснет |

## Логирование

- Только **английский ASCII** (без emoji и кириллицы) — читается в любой кодировке консоли,
  не даёт кракозябр при перенаправлении в файл.
- Все служебные сообщения — в **stderr**; таблица — в stdout.
- Формат: `HH:MM:SS [LEVEL] cc_search: message`; уровень INFO, с `--verbose` — DEBUG.
- Шум библиотек (`cdx_toolkit`, `urllib3`) приглушён до ERROR.

Перенаправление в файл:

```bash
# cmd / bash
python cc_search.py Perm --domain pstu.ru --verbose 2> debug.log

# Windows PowerShell (явная кодировка)
python cc_search.py Perm --domain pstu.ru --verbose 2>&1 | Out-File -Encoding utf8 debug.log
```

## Известная проблема: 504 Gateway Time-out

**Симптом:** запросы к `index.commoncrawl.org` возвращают `504` (реже `502`) стабильно
через ~10–11 с; библиотека повторяет с backoff до 60 с и листает страницы на 404.

**Диагноз (подтверждён экспериментально):** серверная деградация CDX-шлюза — любой запрос,
чья обработка превышает ~10-с cutoff nginx, умирает независимо от шаблона URL, снапшота
и клиентского IP. Это **не ошибка кода**.

Доказательная база:

1. A/B-тест: `*pstu.ru*` и `*.pstu.ru` → одинаковый 504 за ~11 с (форма wildcard не причина).
2. Запрос `*.example.com` к `CC-MAIN-2026-43`, успешно вернувший 2 результата в «окно здоровья»,
   позже даёт 504 даже с чистого IP (другая сеть, без истории запросов).
3. Официальный FAQ: CDX-эндпоинт «часто злоупотребляется и поэтому сильно rate-limited»;
   при 503 — замедляться, при блокировке IP — ждать 24 ч; спать между вызовами,
   не запускать параллельные потоки с одного IP.
4. Стороннее наблюдение (11.09.2026): корректные документированные запросы тоже вернули 504;
   рекомендация — сохранять успешный вывод и возобновлять позже.

**Что делать:**

- не «долбить» сервис подряд; проверить <https://status.commoncrawl.org/>;
- дождаться спокойного окна и прогнать запрос **один раз** → кэш создан;
- дальше демонстрировать из кэша (`--show-text` ходит на `data.commoncrawl.org` — отдельный сервис);
- для массовых/широких выборок официально рекомендован columnar index (Athena / DuckDB) —
  вне рамок данной практики.

Формулировка для отчёта:

> «504 — серверная деградация CDX-шлюза (фиксированный ~10-с cutoff), воспроизводится
> с чистого IP на валидных запросах; подтверждено FAQ и сторонними наблюдениями.
> Клиентская сторона обработана кэшированием, circuit breaker и вежливыми паузами.
> Для массовых фильтраций официально рекомендован columnar index (Athena/DuckDB),
> выходящий за рамки практики».

## Диагностика сервиса

`cc_check.py` — быстрая проверка доступности CDX (3 снапшота, `*.example.com`, limit 2,
замер времени ответа, код выхода 0/1):

```bash
python cc_check.py
```

A/B-проба без retry-шума библиотеки (прямой `httpx`, timeout 30 с):

```python
import time, httpx
for p in ("*pstu.ru*", "*.pstu.ru"):
    t = time.time()
    try:
        r = httpx.get("https://index.commoncrawl.org/CC-MAIN-2024-10-index",
                      params={"url": p, "output": "json", "limit": 2}, timeout=30)
        print(p, "->", r.status_code, round(time.time() - t, 1), "s")
    except Exception as e:
        print(p, "-> FAIL", round(time.time() - t, 1), "s", e)
```

Интерпретация: обе строки 504 → деградация сервиса; 200 на валидном шаблоне → «окно здоровья»,
можно создавать кэш.

## Ограничения

- CDX ищет по URL/домену, **не по содержимому** страниц; полнотекстовый поиск по архиву
  требует columnar index (Athena/Spark/DuckDB).
- Без `--show-text` заголовок страницы недоступен (CDX его не хранит) — в таблице `-`.
- Покрытие архива — выборка веба, а не полный интернет; отсутствие URL ничего не доказывает.
- Публичный CDX-API нестабилен и rate-limited; приложение проектировалось в предположении
  сбоев (кэш + предохранители).
- Daemon-поток после wall-clock капа доживает до выхода процесса — допустимо для CLI.
